# Arvin Zaferani — Personal Website

## 1. Project Goal

Build a personal website for **Arvin Zaferani**.

The primary goal of the website at this stage is **generating full-stack software project opportunities**.

This is not primarily a resume website, developer portfolio, or personal blog.

The website should communicate:

> **Arvin can take a software project from idea to production.**

The visitor should quickly understand:

* Arvin is a full-stack developer.
* He works on real-world web applications.
* He can take ownership of a project end-to-end.
* He has experience building and shipping real products.
* He is available for selected project work.
* There is a clear way to start a conversation.

---

# 2. Brand Positioning

### Primary positioning

**Full-stack developer helping founders and businesses turn ideas into production-ready web applications.**

Alternative core message:

> **I build web products from idea to production.**

The site should emphasize **full-stack development**, not frontend development.

Frontend is a capability, not the primary identity.

---

# 3. Design Direction

## Overall aesthetic

**Minimal + Editorial + Premium + Technical**

The website should feel:

* confident
* clean
* mature
* intentional
* independent
* technically capable
* slightly editorial
* modern without looking like a generic SaaS website

Avoid making it look like a typical developer portfolio.

The goal is:

> **Independent full-stack developer / technical partner**

rather than:

> Developer showing off technologies.

---

# 4. Core Experience

The website should be a **scroll-driven interactive experience**.

Instead of simply presenting:

```text
Hero
Services
Projects
About
Contact
```

the scroll itself should drive the storytelling.

The page can behave like a sequence of chapters.

The user should feel like they are moving through a narrative rather than scrolling through static sections.

---

# 5. Scroll Philosophy

Animations should communicate information.

Do NOT animate elements just for visual spectacle.

Use scroll to:

* transform typography
* reveal information
* transition between concepts
* scale project screenshots
* pin important content
* move between project stages
* reveal process
* create continuity between sections

Avoid:

* excessive 3D
* particles
* random floating objects
* excessive gradients
* flashy developer animations
* animation for animation's sake

The experience should remain minimal even though it is interactive.

---

## Project interaction

Use a sticky/pinned project presentation.

Example:

```text

                  [ LARGE SCREENSHOT ]

              Product · Full-stack · Deployment
```

As the user scrolls:

1. Project title appears.
2. Screenshot enters.
3. Screenshot scales or moves.
4. Project description appears.
5. Technology / role appears.
6. Outcome / production status appears.

# 26. Internationalization

The website must support both Persian (Farsi) and English languages.

**Language switching:**
- Primary CTA and navigation should support language toggle
- Default language: English
- Secondary language: Persian (Farsi)

**Text direction:**
- English: LTR (left-to-right)
- Persian: RTL (right-to-left), requiring layout mirroring

**Content translation key areas:**
- Hero typography transitions (INTRO chapter)
- "WHAT I DO" list in CAPABILITY chapter
- Project case studies in PROOF chapter
- About section content
- CTA text ("START A PROJECT →", "VIEW MY WORK →")
- Technology stack line
- Footer/availability indicator

**Implementation approach:**
- Use next-i18next or similar i18n library
- All user-facing strings extracted to translation files
- Persian translations maintained separately
- Layout components adapt direction based on selected language
- Test both LTR and RTL rendering thoroughly

**Design considerations:**
- Saffron accent color remains consistent across languages
- Typography scale adapts for Persian text length
- Mobile responsiveness accounts for RTL scrolling behavior
- Navigation mirroring when Persian is selected
